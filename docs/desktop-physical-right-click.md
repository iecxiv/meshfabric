# Physical right-click trial

Capture secondary mouse button input before it reaches the Compose touch-click handler, scoped to the live remote image. MainActivity delegates touch/generic motion and key events only to the currently attached desktop canvas capture. Other screens have no capture. Cancel an existing Compose pointer gesture when a generic secondary press or a captured legacy Back down is accepted, preventing a left-click from the old touch path.

The canvas uses the existing fit/zoom/pan projection. The floating controls bar registers an excluded window rectangle in both collapsed/expanded variants. Headers, letterboxing, unsupported coordinates, unfocused/inactive/disconnected sessions and open keyboard/clipboard/settings dialogs do not admit new right clicks. Captured releases can be consumed after leaving the image to prevent a navigation leak.

Native BUTTON_SECONDARY presses use the existing performMouseClick(..., isRightClick=true) path, independent of the selected touch mode and respecting existing mouse-button swapping. This trial is a click, not right-button drag/hold support. The existing sender pairs down/up with its existing delay; disconnect can still prevent best-effort delivery of release.

Legacy KEYCODE_BACK is captured only for mouse-source events over the last known image position (matching device), or an explicitly right-button scan code matching an already owned native stroke. Ordinary keyboard/system Back is not intercepted. Known Linux side/extra/back/forward/task scan codes and observed native navigation button states are excluded. Unknown firmware-generated Back events can be indistinguishable from a mouse navigation button; behavior needs device validation. If no trustworthy hover position or source exists, pass the event rather than globally disabling Back.

Duplicate native/legacy representations are suppressed using per-device input stroke timestamps, not a time debounce. This relies on the OS preserving a common physical-stroke time interval; differing vendor timestamps require further diagnosis. Reset ownership on window focus loss, stop, dispose and activity destruction. Use an identity check so disposal of an old canvas cannot clear a newer owner.

No wheel protocol, touch gesture algorithm, clipboard, terminal or version changes. No key contents, positions or clipboard content are logged. Eight JVM policy tests cover native/legacy deduplication, repeats, release pairing, fast separate clicks, device isolation, reset and ordinary Back/known side-button filtering. They do not prove Android dispatch order, DeX context-menu behavior or actual event-source metadata.

Acceptance: physical right-click within remote image in every touch mode; one remote context menu, no local Back or duplicate left click. Test with zoom/pan, image margins, floating controls, dialogs, true Android Back, physical keyboard Back, dedicated mouse side navigation buttons, fullscreen, rotation and focus loss. Recheck wheel, touch gestures, keyboard and clipboard. Publish implementation only after debug compilation and JVM tests succeed; verify on the user's mouse/Android/DeX setup before calling the trial complete.
