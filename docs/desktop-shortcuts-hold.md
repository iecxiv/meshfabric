# Desktop shortcuts and held modifiers

Append two sections after the existing F-key row in the keyboard/shortcuts dialog. Existing text, quick actions, editing keys, special keys and F keys remain in their original order and location. New UI uses Material 3.

Hold: Ctrl, Shift, Alt and Win are toggles, highlighted while owned by the Hold section. Closing the dialog keeps them down for canvas interaction. Release all removes all four Hold owners without releasing a real physical key that is still down. State is per remote desktop node and is not persisted. On leaving the screen, lifecycle pause, disconnect or ViewModel destruction, cancel pending actions and attempt releases while the transport is available. A lost connection cannot acknowledge releases, but local state is cleared and holds are not replayed on reconnect.

Shortcuts: execute, reorder up/down, remove, add modifiers and a key (or modifier-only), restore defaults. Up to 64 presets stored locally in the app's desktop_shortcuts_v1 preferences; empty lists stay empty. Data contains only numeric virtual-key combinations, not typed text. Presets are shared across desktop nodes in this app installation. Key selection includes letters, digits, navigation/special keys and F1-F24. Defaults match the provided seven-row reference.

Route existing ViewModel single keys, combinations, physical keyboard events and Ctrl-Alt-Del through a shared ownership engine. Temporary action owners and physical input cannot release a UI Hold owner. Preserve repeat downs for ordinary physical keys. Actions keep the existing staggered combo timing and release in reverse order. Each engine freezes its socket identity; delayed or canceled releases cannot target a replacement transport. No transport protocol, mouse/wheel, clipboard, terminal, version or existing key-row changes.

Fifteen JVM test cases cover the four toggles, release-all, ownership overlap, physical/Hold coexistence, repeats, asynchronous actions, replacement socket, disconnect, ordered preset persistence, corrupt data, empty lists and defaults. The publication workflow must compile assembleDebug and pass testDebugUnitTest before committing the implementation. Android UI/device verification remains required: hold Ctrl and click the canvas, close/reopen dialog, execute Ctrl+C while Ctrl is held, combine multiple holds, release all, disconnect/reconnect, rotate and leave the screen; verify existing rows and physical keyboard behavior.
