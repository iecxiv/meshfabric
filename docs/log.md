# Registro / Log

Events queries the server with a unique tag, selected event-action filter and selected count. UI choices are 60 (default), 120, 250, 500, 1000 and Unlimited. Unlimited omits limit in the server request and imposes no artificial count, frame-size or msg-description-length ceiling. Finite selections retain their selected count and existing frame/text protections. Identity metadata and JSON types remain validated. Actual device resources, timeouts and server permissions still apply; failures are not presented as complete histories. Legacy helper calls retain 200 for compatibility, not as a UI ceiling.

Changing selection starts a new bound request and retires prior replies. Search filters received records locally. Account/server changes, pause and observed access changes clear data. Server authorization remains authoritative; the history is not a complete audit log. Numeric msg values retain their literal representation. Unknown event types remain visible with a generic icon.

Read-only history; no event deletion or automatic mutation retries. Decode errors, explicit denial, timeout and empty results remain distinct. Automated checks do not replace live-server compatibility or physical-device visual review. Management-channel placement and previous-login dialogs are outside this change. Full validation is required before final dev integration.

Selectors use the Activity selector shape, colors, typography and exact anchor/menu width. Type options include icons; count options are text-only and centered. Clickable rows open selectable, scrollable read-only details. Explicit scalar detail fields are retained; runcommands additionally keeps literal cmds/cmdType/runAsUser, and nodemeshchange keeps oldMeshId/newMeshId. Arbitrary raw payload, cookies, tokens and password fields are not retained. Details are reset with snapshot/selection invalidation and account/server changes. Real-server and physical-device visual checks remain required.

Events selectors share one row with weights 2:1 after an 8 dp gap, inside a centered container capped at 560 dp. Each popup matches its own measured anchor width. Headers and options wrap without ellipses; option rows grow vertically with their text, including enlarged fonts. Previous overflow assertions remain mandatory, with per-type diagnostics. The former text-measured sizing and vertical control reflow are superseded.

Event content review against meshcentral@1.3.1 meshuser.js: runcommands has generic msg plus cmds/cmdType/runAsUser; manual uses msg; changenode/nodemeshchange may expose a nested node; removenode carries historical device/group names in msgArgs[0:2]. Only those specific structured name arguments are interpreted, not arbitrary message templates. No unverified per-action payload is invented. Relay generic scalar details remain supported; this is not a complete audit of all server producers.
Cards and read-only dialogs share device(group); node and mesh IDs are shown only in details, not as card metadata. Event names win. Missing names are filled from the same active client inventory (not the device-list search result); fallback origin is tracked internally, not historical evidence; its explanatory UI notice is suppressed by request. Mesh-specific group lookup prevents current group names from being attached to a different historical mesh ID. Domains are preserved in ID matching. Inventory changes retire open details; account/server scope remains keyed. Command contents remain selectable in details and searchable locally, never sent for execution or added to diagnostics. Commands can contain sensitive user data; there is no automatic export.
Reference: https://unpkg.com/meshcentral@1.3.1/meshuser.js . Live-server and physical-device checks remain pending.

Events search is collapsed by default, opened from the app-bar search icon, and displayed below the section tabs with focus/keyboard behavior matching Activity. Header close clears the query and hides the keyboard; the field clear button keeps search open. Search still includes hidden node/mesh identifiers and command content. Query/visibility are saved per Events tab within the existing account/server scope. The permanent in-panel search field is removed.
Visible filtered events are grouped by their event timestamp in the current local timezone, newest day first, using Activity date-band shape, padding, typography and primaryContainer/onPrimaryContainer theme colors. Missing event times form a separate localized unknown-date band and are never assigned the receive date. Duplicate events are preserved. Device/group, commands and the existing details dialog are otherwise unchanged. Tests are updated to open search from the header and require identifiers absent from cards but present in details.

Events refresh is an icon immediately before search in the app bar, not a content button. It loads the currently selected type/count without changing the active query, and is disabled while loading, disconnected, without an actor or with stale selection. The inventory-origin and finite-query-ceiling notices are hidden in cards/details; parsing, identity resolution, requested limits and unlimited behavior are unchanged. No management-channel status is added to Events.
Management device groups, users and user groups move their existing refresh/reconnect action from Server actions into the app bar owned by the same ProfileScreen session. My account has no refresh action. User groups preserve directory-specific gating and explicit loadUserGroupDirectory after refresh. Existing connection-status widgets, spacing constants, dialogs and Activity app bar are not modified.

Presentation refinement: event cards use device (group) with an inserted space; the details Device value is the unadorned node name, with Group separate. User-edit login history retains its existing dialog modifier, properties, content maximum height, typography, spacing and navigation, adding only row colors from the account palette. The account previous-logins view alone uses a dedicated read-only dialog with the user-editor reference geometry (max 640 dp, 94% width, 68% screen content-height cap, 10 dp gaps), date/message/divider hierarchy and Back/Close actions. All other account dialog code and wire behavior are unchanged. Both login views share the colored entry renderer and existing date formatter, use server-order records, preserve the 200-row display bound, and keep unknown outcomes neutral. Server Statistics moves its existing refresh callback into the app bar only on tab 1, preserving selected hours and busy/connection gating; period selectors, charts, exports, reader and other server actions are unchanged. Validation is focused and builds/installs APKs once; physical visual review and server verification remain required.
